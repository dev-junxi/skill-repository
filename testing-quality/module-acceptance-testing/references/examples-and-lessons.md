# 参考实现与迁移

本skill提炼自Lumos的记忆客户端验收目录。原始资料定位：仓库 `lumos-server-java`，模块 `components/lumos-ai-memory-spring-boot-starter`，目录 `src/test/java/com/lumos/component/aimemory/testcase`。

原目录只作可选参考。新机器或目标模块没有它时，使用本skill的流程、契约和模板即可；不要要求用户先复制记忆模块工程。

## 可参考的源码

| 文件 | 可复用的设计 |
|---|---|
| AcceptanceCase / P0Samples / P1Samples / P2Samples | 用例ID、优先级、预期与可执行动作分离 |
| AcceptanceContext | 公共入口、严格断言、来源检查、有上限轮询 |
| AcceptanceRunner | 独立用例继续执行、不可用时显式SKIP、finally清理、增量落盘 |
| AcceptanceEvidence | 客户端边界收集脱敏合成参数、响应及耗时 |
| AcceptanceBanks | 创建前登记、删除后确认、按原清单恢复清理 |
| AcceptanceReports | 六列表、状态分布、带口径的指标与部分执行边界 |
| MemoryLifecycleClientTest | 详情/列表DTO差异、空值、请求字段和来源契约 |
| AcceptanceRunnerTest | 解析失败不跳过下一例、传输失败仍清理、丢失回执、恢复清理及部分计划 |
| P0CorrectionSampleTest | 用户输入来源确实发送、服务忽略字段或保留旧关联时仍失败 |

参考实现也存在需要适配的限制：连续两次5xx停止调用是该运行的策略；“必须执行全部三个优先级”是该目录的结论口径；八项指标属于记忆业务。新模块应使用自己的完整目录和必需能力政策，而不是永久绑定这些数值。

## 失败经验及其通用含义

| 原问题 | 复用时应做的事 |
|---|---|
| PATCH详情返回实体数组，列表返回实体字符串，DTO解析失败 | 分别验证每个响应形态。HTTP已成功而DTO错误属于封装缺陷，不能自动称为服务断网 |
| 回答认出姓名与别名，但底层三个实体ID未合并 | 显示层正确不代表状态模型正确。按真实产品要求分别检查显示结果与规范ID/关联 |
| 修改正文后，原上下文、实体和来源仍影响回答 | 列出修改操作承诺更新的字段及派生关系，显式记录用户纠正来源，并验证读取结果。审计reason不自动等于业务上下文 |
| 原始日记不应随手工事实纠正被改写 | 区分不同资源的生命周期：原文、当前状态、派生状态、历史归档不能混用一个“全部消失”判据 |
| 改metadata未改正文，被误解释成正文替换用例 | 单例明确本次改变的维度；不能把一种更新通过推广到另一种 |
| 列表省略来源字段，误判源记忆悬空 | 从契约支持的详情入口补证，验证来源确实存在；返回空对象不代表已有证据 |
| 时间过滤参数被服务忽略 | 用边界内、边界前、边界后的合成数据验证；不能客户端过滤完再给服务PASS |
| 删除响应成功，读取配置仍返回默认值 | 使用权威可见性入口确认删除，不把默认配置当对象仍存在或已删除的证明 |
| 调用层catch吞掉解析原因 | 保留安全错误分类，不打印敏感正文，不把所有无状态异常当网络故障 |
| 历史FAIL随测试修改被覆盖 | 新run_id复测，不改历史证据；框架单测和真实服务验收分开报告 |
| 手写README/实施计划未含front matter | 生成文档前读仓库规则，交付前运行文档卡口，避免只验Java编译 |

## 迁移示例：认证模块

入口选择公开登录、当前用户和退出/撤销接口；测试用户来自项目既有隔离fixture或按测试关联标记创建。密码、验证码和token只在内存/安全配置中使用，证据记录脱敏投影。

可选用例：

- 合法登录后读取自身资料，断言用户ID和权限；这是权限反例的正命中前置。
- 无token返回预期401、失效token不被接受；401是此例的预期结果，不触发全局不可用策略。
- A身份请求B的受保护资源，不只检查HTTP状态，也检查响应体和附加字段无B内容。
- 重复退出/撤销的幂等语义由实际契约决定，不预设所有系统都应返回同一状态码。

报告指标选认证成功/拒绝契约、越权失败、撤销可见延迟等；不复制记忆召回率、token预算或bank清理。已有测试用户不可自动删除，清理只作用于该运行明确拥有的资源。

## 迁移示例：订阅事件模块

入口选择公开事件处理API或模块对外的已验证事件入口，使用提供方沙箱事件/离线签名fixture。没有真实扣费授权时不创建真实付费订阅，不修改共享账户的状态。

可选用例：

- 验签有效事件产生预期权益，验签无效事件被拒绝且无状态变更。
- 相同event_id重试多次，权益和发放记录不重复。
- 已授权的事件乱序或重复投递，按该模块的版本/时间规则得到确定结果。
- 取消/过期后权益按契约生效，异步任务有明确终态和截止时间。

业务断言从稳定读取接口观察，不绕过事件入口直接改权益表。性能使用事件到权益可见延迟；副作用使用沙箱计数或出站替身断言。用报告区分“模拟提供方通过”和“提供方真实沙箱验证”。

## 迁移示例：非Java模块

Python可用pytest fixture/CLI、TypeScript可用现有测试runner；保留用例状态、证据引用和资源归属约束，复用已有夹具和环境开关。不要为套模板引入Java类、Spring或新的跨模块依赖。
