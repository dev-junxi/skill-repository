# 执行与结果契约

## 用例状态与运行结论

状态描述单例结果，不等同于构建进程退出码：

| 状态 | 使用条件 |
|---|---|
| PASS | 必需的自动断言实际执行且满足，不存在待完成的必需人工评审 |
| FAIL | 已取得足够证据，实际业务结果违反预期 |
| ERROR | 非预期调用、解析、等待或执行错误，无法完成预设验证 |
| UNSUPPORTED | 已有明确契约或能力证据表明不支持；仍需报告其对业务的影响 |
| SKIP | 选中了但未执行，记录具体原因；不得计入通过 |
| REVIEW | 已完成部分自动检查，但开放语义或必需人工检查尚不能定论 |

没有断言、无依据或“没有抛异常”不自动产生PASS。对预期错误走正常断言路径：例如“未认证请求返回401且没有泄露数据”可以PASS；不是把HTTP异常直接映射成ERROR。

能力是否支持先看契约再判状态；404既可能是预期不存在，也可能是路径/数据问题，不能统一转成UNSUPPORTED。参考实现曾把405/410/501作为能力提示，新模块必须确认这些响应在该业务中的含义。

整体结论至少区分：

- 存在阻塞：必需能力FAIL/ERROR、不支持必需能力，或清理未确认。
- 证据不足：有未运行/未复核必需项，实际执行不覆盖选中计划，或选中计划不足以代表完整验收范围。
- 所选范围通过：选中项全部PASS且清理完成；未选中范围仍未知。
- 完整范围通过：已定义的完整必需范围全部执行通过，且清理完成。结论只覆盖本轮样本，不扩展成生产整体保证。

根据项目发布策略决定退出码。常见默认：必需能力失败和清理失败返回非零；严格模式还把SKIP/REVIEW视作失败。可选能力是否阻塞需预先定义，不能在运行后调整。即使进程退出0，也不能把REVIEW/SKIP写成通过。

## 最小结果与证据字段

每轮run记录：run_id、模块/仓库版本、服务版本和来源（自动读取或运行方声明）、无凭证目标标识、时区、配置摘要、完整目录ID、选中ID、开始/结束时间。没有探测到的版本标“未核验”，不要猜测。

每例result记录：case_id、priority、scenario、input摘要、expected、status、actual、duration_ms、checks、evidence引用、skip/review原因及资源清理结果。时间边界用固定业务时钟/显式时间戳，不能让本机时区决定语义。

每项check记录：指标类别、检查对象/预期、是否通过、实际证据。分清“几个断言失败”和“几条泄露事件”：未做事件去重时只报告失败断言数。

每条调用证据记录：操作名、脱敏参数、响应或安全投影、耗时、技术调用状态、错误分类及HTTP/业务状态、可见用量。技术调用success不等于业务用例PASS。失败调用也进入耗时与失败统计，耗时边界注明是否含清理/重试。

真实敏感数据不能为了报告而落盘。优先合成数据；确需验证生产只读数据时使用最小投影和既有脱敏规则。未知异常不得把原始响应正文或带凭证URL写入报告。

## 执行顺序

```text
建立运行记录与完整/选中计划
for each selected case:
    若依赖确不可用/此前中断 -> SKIP，记录原因
    否则执行该例及检查 -> PASS / FAIL / REVIEW / ERROR / UNSUPPORTED
    finally:
        清理本例资源，持久化清理证据
        持久化该例结果；清理失败不覆盖原始业务错误
    对独立用例继续执行；刷新分类和总体报告
finally:
    再尝试有限次清理本轮未确认资源
    保留异常退出前的结果和未执行计划，完成最终报告
```

框架可串行执行以简化归属和故障判断。并行仅在隔离、限流和日志关联已设计时启用，不从此模板默认增加并发。

环境不可用判断需分层：

1. 响应可解析且是预期业务拒绝：执行业务断言，继续。
2. 收到响应但DTO解析失败：ERROR，继续其他独立用例。
3. 确认传输失败、非预期测试凭证失效：停止该依赖后续调用，记录SKIP，仍清理。
4. 连续非预期服务端错误：使用有上限的熔断策略；参考运行采用连续两次5xx，可按模块配置，不能套用到专门测试5xx的案例。

异步轮询记录每次状态，截止时给出最后状态和任务ID；failed/cancelled等终态立即结束。没有已知幂等键或只读性质的写操作，不因超时盲目重试。

## 资源生命周期

资源清单记录：目标环境指纹、run_id、case_id、资源类型、预分配ID/幂等键/测试关联标记、服务端实际ID、创建意图、确认创建、确认移除及最近清理错误。

创建请求发出前原子保存意图。对于服务端分配ID的资源，先记录可用于恢复定位的测试关联标识，拿到响应后补ID；没有可靠恢复定位手段时，不在不可逆/共享环境启动该写入测试。

只删除清单中归属已核验的对象。回复成功后读取具有权威语义的状态确认删除；某些“读取配置”接口会对不存在对象返回默认值，因此不能盲用它确认存续。最终一致系统使用有上限的可见性等待。

恢复入口必须同时校验目标环境、run_id和单个资源归属。不能仅凭文件里写了某个ID就删除它，也不能仅凭一个宽泛名称前缀批量删除。清单不保存凭证，恢复执行从运行环境读取凭证。

删除404是否可视为完成，由目标资源接口的契约决定。清理失败重试次数有限，保留精确资源清单；恢复结果另存，不重写历史业务结果。进程被强制结束、网络断开或清理接口故障时，明确残留或未知状态。
