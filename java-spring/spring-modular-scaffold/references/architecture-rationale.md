# 架构来由

这份文档回答「为什么必须这样」。日常使用不需要读；**改动生成出来的结构之前应该读**。

## 六条铁律为什么不可关闭

| 铁律 | 它防的是什么 |
|---|---|
| 三层文档（根 / 就近 / ADR） | 所有模块知识堆进一个根文件，那个文件会涨到几百行且必然过期 |
| 索引**脚本生成** | 手写索引是第二份真实来源，必然与实际模块列表漂移 |
| ADR 带 `Verify:` 行 | 没有可执行判据的决策记录，三个月后没人能确认它是否还成立 |
| 每条规则配违规 fixture | 一条从未在违规代码上红过的规则，和没有规则等价——只是多了虚假的安全感 |
| `domain` 零框架依赖 | 领域模型一旦依赖框架，就无法脱离容器测试，分层退化成命名约定 |
| `CLAUDE.md` 只做指针 | 手工维护多份上下文副本必然各说各话 |

**它们互相咬合。** 没有卡口，文档必漂；没有违规 fixture，卡口可能空转；没有 domain 纯净，分层只是命名约定。任一条做成可关闭，其余的价值一起塌。

## 这套结构来自哪里

原型是一个 Rust 服务的 Java 重写。上一版在生产里跑了很久，攒下几十条血泪教训，这套结构是针对那些教训设计的。几个直接对应：

**上下文文件漂移**：上一版有三份上下文文件（`CLAUDE.md` 470 行、`AGENTS.md` 89 行、`GEMINI.md` 61 行），内容互不相同，后两份分别死了 5 个月和 6 个月。这不是没人负责，是「手工维护多份真实副本」这个结构必然导致的。所以现在只有一份真身 + 一个指针。

**共享测试库**：上一版集成测试连一个共享的、不清理的远程库，由此衍生出至少六条独立的坑——跨分支迁移撞号、测试残留让 `contains` 断言恒真、串行化掩盖并发缺陷、本地实例悄悄顶替端口让「全绿」报告是假的。换成 Testcontainers 后这一整类问题不复存在。

**跨模块依赖失控**：`A-web → B-api` 与 `B-web → A-api` 同时存在时，Maven 不认为是循环（不同 artifact），ArchUnit 的包循环检测也抓不到（不同包）。**现有工具都看不见这种双向依赖**，所以需要快照 + diff 让它在 PR 里显形。

**日志泄漏用户内容**：加密列的明文最常见的泄漏路径不是日志语句本身，而是被塞进异常 message 后在几层调用之外被原样打印。所以脱敏做两层（字段名遮蔽 + 路径前缀整体抑制），且路径清单在配置里而非代码常量。

## 「被证明会失败」为什么是核心

这是整套设计里最容易被当成形式主义、实际最值钱的一条。

**假绿有三种形态，每种都真实发生过：**

**① 规则匹配不到任何东西。** 一个包匹配表达式写错（`..domain..` 打成别的）的 ArchUnit 规则，在生产代码上匹配零个类 → 空集通过 → 永远绿，什么都没管住。

**② fixture 红了，但红的原因是错的。** ArchUnit 在规则零匹配时**也抛 `AssertionError`**。所以只断言「抛了异常」的 fixture 测试，在规则被改坏后照样通过——实测把三条 domain 规则的包名改成匹配不到，`Tests run: 16, Failures: 0` 全绿。这就是 `assertRuleFires` 必须再断言「失败信息点名了预期的违规类」的理由：它同时排除「没抛」和「因错误原因抛」。

**③ 验证脚本自己是绿的。** 对管道取 `$?` 取到的是管道**最后一个**命令的状态，恒为 0。原型执行期真踩过：`mvn ... | grep ... | head` 后取 `$?`，得出「12 个依赖坐标全部验证通过」的结论，实际 `mvn` 因为命令不存在压根没执行（退出码 127），是「本地仓库里只有 1 个 artifact」这条独立证据把它推翻的。

所以 `verify.sh` 的第 6 条独立于 fixture 存在：fixture 证明规则**逻辑正确**，第 6 条证明规则**扫到了真实代码**。两件事必须分开验证。

## 几处容易被质疑的选择

**为什么不用 WebFlux**：为了 SSE 把整个代码库染成响应式（`Mono`/`Flux` 穿透到 domain 层）是笔亏本买卖。JDK 21 有虚拟线程之后，`SseEmitter` + 虚拟线程足够，且领域模型能保持是普通对象。

**为什么 api/web 双 module 不做成选项**：跨模块依赖只经 `-api` 是核心不变量，由 Maven 编译期强制。退化成单 module 后它只能靠 ArchUnit 测试，而测试可以被跳过、可以被 `@Disabled`。**编译期约束和测试期约束不是一个量级。**

**为什么根 pom 必须显式声明 `<groupId>`**：monorepo 模式下 parent 是 `spring-boot-starter-parent`，不声明就会继承成 `org.springframework.boot`，子模块的 parent 坐标全部对不上。standalone 模式恰好正确，所以这个 bug 只在 monorepo 下暴露——生成器实测踩过。

## 已知的取舍代价

| 选择 | 代价 |
|---|---|
| Stateless JWT 鉴权 | **没有服务端强制下线能力**，靠短 access TTL 替代。要做撤销需引入黑名单存储 |
| 独立 parent repo | 每次改 parent 要发版 + 改下游版本号。只有多项目共享基线时才回本 |
| api/web 双 module | 模块数翻倍，小项目是纯开销 |
| 应用层零状态 | 限流要挪到网关层，精确分布式限流需要引入 Redis |
| 持久层组件 | 依赖私有 artifact `com.lumos:model-view-builder`，拉不到的机器上构建失败 |
